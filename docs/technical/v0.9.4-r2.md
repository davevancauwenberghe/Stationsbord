# v0.9.4-r2

## Overnight journeys

iRail's stop connection URI carries that stop's calendar date, which can differ
from the journey's origin date. Verified against IC 723 on 11–12 October 2026:

| Stop | Scheduled departure | Connection date |
| --- | --- | --- |
| Antwerpen-Centraal | 11 October, 23:36 | 20261011 |
| Gent-Dampoort | 12 October, 00:24 | 20261012 |

The following day's vehicle response departs Gent-Dampoort on 13 October.
Board details validate the returned origin date and match the board's scheduled
arrival/departure instant at the selected station. A missing/mismatched service
allows one preceding-date request. Only a matching route is displayed. The
resolved date is retained for composition and background route refreshes;
delays and cancellations do not change the scheduled anchor. Transient upstream
failures do not trigger another day's lookup.

This avoids a blanket early-morning date shift: a train beginning after midnight
on the selected calendar date remains on that date. Train-number searches still
use their existing active-previous-service check before 04:00 in live mode;
explicit custom dates select the journey's origin date. Summaries show origin
and final-stop dates for overnight journeys.

## Board fullscreen

The board button requests fullscreen on the root document during the user's
click. The dialog remains within that fullscreen surface. Exiting native
fullscreen also exits board mode. Unsupported or rejected requests retain the
viewport-filling layout, without a maximum width or surrounding page chrome.
Controls and Escape still exit this layout. Safe-area insets protect content.

Some browsers, notably iPhone Safari, cannot enter document fullscreen; their
browser controls remain under OS/browser control. Installed standalone apps
avoid the normal browser toolbar. The Fullscreen API does not guarantee that
every OS overlay disappears.

## Installed-app startup

An early, external script shows the existing mark, title and spinner only in
standalone/fullscreen display mode or Apple's standalone mode. The surrounding
page is temporarily inert. The initial search completion removes the overlay;
an eight-second fallback restores the page if startup fails or an API is slow.
Reduced-motion preferences disable spinner rotation. Normal browser visits do
not show the overlay. The Content Security Policy remains unchanged.

Apple startup PNGs cover common iPhone/iPad screen sizes in portrait/landscape
and light/dark appearance. These are **static**: animation begins in the HTML
screen after it loads. Native launch behavior, support for device-specific
images and appearance are controlled by the OS. A native launch image follows
the OS colour scheme; the document then applies Stationsbord's saved theme.

The committed assets are generated from Stationsbord's own SVG mark. To
regenerate them, install Playwright and its Chromium browser in a development
environment, then run:

```sh
node scripts/generate-launch-assets.cjs
```

If Playwright is installed outside this repository, set
`STATIONSBORD_PLAYWRIGHT_MODULE` to that module's absolute path. The generator
updates both PNGs and their startup-image links using the package version.
There is no new runtime dependency.

## Shared styling

The train result uses the same panel, heading and actions as the liveboard:
Bahnschrift/system font fallback, sign colours and theme-aware controls. The
search forms keep their separate station and date-only train inputs.

## Verification

78 Node tests pass, including IC 723's scheduled anchors, arrival boards,
cancellations, DST boundaries and legitimate services originating after midnight.
Headless Chromium checks cover 16 phone/tablet/desktop layouts in light and dark
appearance (390, 820, 1440 and 2560 pixels), with no detected WCAG A/AA violations.
14 behavior scenarios verify overnight resolution and refresh, explicit dates,
retained results after failed submissions, native fullscreen entry/exit and
unsupported/rejected fallback, installed startup, reduced motion and the boot
timeout. All 64 native PNG dimensions and theme links are verified. Actual
iOS launch presentation still requires checking on a physical installed device.
